Agent roles starts agents from named role definitions. A role bundles a system prompt, a model, MCP servers, pre-approved tools and provider options, and lives as a YAML or JSON file in your repository instead of being retyped for every agent.

Pass `PASEO_AGENT_ROLE=<name>` in the environment when creating an agent, for example `paseo run --env PASEO_AGENT_ROLE=reviewer`. The plugin rewrites the agent's configuration before it starts. Agents created without the variable are left untouched, and an unknown role name makes creation fail.

The Agent roles sidebar item opens a screen that lists roles and their sources, shows each role's prompt, model and tools, edits your own roles in `~/.paseo/roles/`, and starts a new agent with a chosen role.

Roles are read from `.paseo/roles/` in the agent's working directory, then from `~/.paseo/roles/`, then from any git repositories you configure on the screen (shallow-cloned and re-fetched every few minutes with the daemon's own git credentials), then from the bundled examples: implementer, reviewer, qa, investigator and babysitter. Git sources are optional. Edits to git roles, and user roles you promote with Save to git, are committed and pushed as a pull request branch (default) or straight to the branch, with the same git credentials. An optional write-only GitHub token lets the screen open the pull request in one click; without it you get a prefilled link. The plugin talks to the network only for the git sources you configure and, with a token, the GitHub API. Paseo has no provider-independent limit setting, so limits are passed through as provider options.
